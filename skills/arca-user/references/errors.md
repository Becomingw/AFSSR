# 报错对照

先记住两件事：

1. 每个响应都带响应头 `x-trace-id`，它就是**请求 ID**。报问题时带上它，管理员才能查到这一次请求。拿法：`curl -i`，或客户端的调试日志。
2. 网关自己返回的错误体是 `{"error":{"type":"http_error","message":"…"}}`；走 `/v1/messages` 时是 Anthropic 风格 `{"type":"error","error":{…}}`。

下表中"实测"表示在运行中的网关上复现过；其余来自代码。

| 你看到的 | 状态 | 含义 | 你该做 | 来源 |
| --- | --- | --- | --- | --- |
| 无效的API密钥 | 401 | 密钥错误、被禁用、过期或已删除，或用户被停用 | 核对密钥和请求头；到「API 密钥」页看状态；仍不行联系管理员 | 实测 |
| API Key 不允许从当前 IP 访问: `<ip>` | **401**（不是 403） | 密钥设置了 IP 限制，当前出口 IP 不在名单里 | 在「API 密钥」页修改 IP 限制，或换到允许的网络 | 实测 |
| 该密钥已被管理员锁定 | 403 | 管理员锁定了这把密钥 | 联系管理员 | 代码 |
| 当前用户、用户组或密钥的访问控制策略不允许访问模型 `<m>` | 403 | 你没有这个模型的权限 | 换有权限的模型；或向管理员申请 | 代码 |
| …不允许访问 `<provider>` 提供商 / `<format>` 格式 | 403 | 密钥被限制了供应商或接口格式 | 向管理员申请；换用允许的接口 | 代码 |
| 请求缺少有效的用户或 API Key 认证上下文，无法选择上游提供商 | 503 | **没带密钥**（请求头缺失或格式不对） | 带上 `Authorization: Bearer sk-…` | 实测 |
| a model is required to evaluate internal usage budgets | 400 | 请求体里没有 `model` | 加上 `model` 字段 | 实测 |
| 没有可用提供商支持模型 `<m>` 的同步请求 / 流式请求 | 503，响应头 `x-aether-local-execution-runtime-miss-reason: candidate_list_empty` | 模型 ID 写错，或这个模型当前没有可用上游（被停用、映射缺失） | 用 `/v1/models` 核对精确 ID；确认无误就带请求 ID 反馈。注意：**未知模型在生成接口上是 503，不是 404** | 实测 |
| 已尝试所有本地执行候选提供商，但没有任何候选成功完成请求 | 503 | 所有上游都失败了（网关已重试并切换过候选） | 稍后重试；持续出现就带请求 ID 反馈 | 实测 |
| 上游渠道达到限流或额度限制（HTTP 429），请稍后重试 | 429 | **上游**的限流或额度问题，不是你的 Arca 预算 | 等一会儿重试 | 实测 |
| 使用额度已达到上限，请稍后重试 | 429，`X-RateLimit-Scope: plan` | 你的 Arca 美元预算用完 | 看 [quota-and-usage.md](quota-and-usage.md) | 实测 |
| 请求过于频繁，请稍后重试 | 429 | 每分钟请求数上限 | 降低频率 | 代码 |
| 服务繁忙，请稍后重试 | 503 | 网关高负载 | 稍后重试 | 代码 |
| 当前 AI 请求在本地执行规划阶段超时 | 503/504 | 网关内部规划超时 | 稍后重试 | 代码 |
| 上游请求体转换失败 | 503 | 所有候选都无法把你的请求转换成上游格式（协议转换问题） | 换成与客户端协议同族的模型；简化工具定义；带请求 ID 反馈 | 代码 |
| Route not found | 404 | 路径不存在，通常是 `/v1` 写多或写少 | 对照 [client-setup.md](client-setup.md) | 实测 |
| Use /v1/responses, /v1/messages, or /v1/chat/completions for model generation | 404 | 用了已停用的 Gemini 原生生成接口（`/v1beta/…`） | 改用三种受支持的接口之一 | 实测 |
| Commercial features are not available in AFSSR internal gateway | 404 | 访问了钱包、充值、支付、推荐等已停用功能 | 这些功能在内部网关里不提供 | 代码 |
| The model `'<id>'` does not exist（`model_not_found`） | 404 | 仅出现在 `GET /v1/models/<id>`：这个模型 ID 不存在或你不可用 | 用 `GET /v1/models` 查看可用列表 | 实测 |
| internal server error | 500 | 网关内部错误 | 带请求 ID 反馈 | 代码 |

## 几个容易误判的点

- **上游自己的 401/403/404/5xx 不会原样转给你**：全部候选失败后统一变成 503 的网关提示。所以看到 503 时不要以为是你的密钥有问题；要看响应头里的 `x-aether-local-execution-runtime-miss-reason`。
- **上游 400 在实测里最终也是 503**（「已尝试所有本地执行候选提供商…」）。如果怀疑是你的请求参数不被上游接受（比如不支持的参数、工具定义），简化请求后重试，并把请求 ID 报给管理员，他们能看到上游返回的原始错误。
- **流式响应中途出错**：HTTP 状态已经是 200，错误会以流里的 error 事件出现，网关不能再改状态，也不会重试这一轮。重试这一轮对话即可。
- 带请求 ID 反馈时，可以勾选"附上安全诊断摘要"，它会写明各阶段（身份、模型权限、额度、候选、转换、代理、上游、流）是否正常；`unknown` 的意思是**没有证据**，不是成功。

# 额度与用量

## 额度是什么

Arca 不是按充值计费的平台，没有钱包、充值、兑换码、推荐奖励（这些页面和接口已停用，访问会 404 或跳回仪表盘）。用量由管理员设置的**美元预算**限制：

- **总额度窗口**：最近 5 小时（滚动窗口，用量随时间逐步释放，没有固定重置时间）、每周、每月。没配置的窗口表示不限。
- **模型 / 模型族子额度**：针对某个模型或一组模型的额外上限，可能带"每日额度"。子额度的用量**同时计入**总额度，一次请求必须同时满足所有适用的窗口。
- **个人额度会替换所属分组的额度**，不是叠加。
- **"无额度上限"**只表示美元额度不限，不代表模型权限、请求频率和并发限制也不限。
- 费用在请求发出前先**预估并预留**，结束后再结算。正在处理的请求占用的预留会显示为"处理中"。同一用户的所有密钥、HTTP 和 WebSocket 共用同一份额度。
- 没有配置任何预算 ≠ 获得了模型权限；能用哪些模型由管理员的模型访问策略决定。

## 在哪里看

| 想看 | 位置 |
| --- | --- |
| 各窗口已用、处理中、剩余、重置时间 | 控制台「个人资料 → 用量与权益」 |
| 额度上限概览 | 「仪表盘」顶部卡片（只显示上限，不显示剩余） |
| 自己的调用记录、按模型和格式统计 | 「使用统计」 |
| 当前能用的模型 | 「模型目录」，或 `GET /v1/models` |
| 近一年的用量热力图、近 5 次调用 | 「个人资料 → 用量与权益」 |

页面写着"额度暂不可用，不代表没有额度"时，是读取失败，不是额度为零，稍后刷新。

「用量费用」是按标准价格估算的费用，只用于参考；真正扣减额度的是结算账本。

## 额度用完时的表现

调用返回 `HTTP 429`，响应体：

```json
{"error":{"type":"plan_usage_limit_exceeded","message":"使用额度已达到上限，请稍后重试",
  "details":{"metric":"actual_cost_usd","window":"rolling_5h","limit":10.0,"retry_after":18000}}}
```

响应头同时带有：`Retry-After`（建议等待秒数）、`X-RateLimit-Limit`、`X-RateLimit-Remaining`、`X-RateLimit-Scope: plan`、`X-RateLimit-Metric`、`X-RateLimit-Window`。

- `window` 取值：`rolling_5h`、`calendar_day`、`calendar_week`、`calendar_month`。告诉你是哪个窗口用完。
- 走 `/v1/messages` 时响应体是 Anthropic 风格，类型为 `rate_limit_error`，但响应头相同。
- Responses 的 WebSocket 连接超限会以关闭码 `1013` 结束。
- 区分：**上游限流**也是 429，但信息是「上游渠道达到限流或额度限制（HTTP 429），请稍后重试」，没有 `X-RateLimit-Scope: plan`。那不是你的预算问题，等一会儿重试。

怎么办：看 `window` 判断多久恢复（5 小时是滚动释放，周/月到重置时间）；急用就向管理员说明需求申请调整，**不要**换用别人的密钥。

## 其他你可能遇到的限制

| 现象 | 含义 |
| --- | --- |
| 429「请求过于频繁，请稍后重试」 | 触发了每分钟请求数上限（用户或密钥级别） |
| 密钥并发上限提示 | 同时进行的请求太多，等已有请求结束 |
| 503「服务繁忙，请稍后重试」 | 网关处于高负载，稍后重试 |
| 429「所有可用上游账号当前均已达到并发或 RPM 上限」 | 上游账号都满了，稍后重试 |

## 请求的取消与费用

默认情况下，客户端取消一个流式请求后，网关仍会把上游响应读完并结算用量，所以**取消的请求仍可能消耗额度**。这是管理员的路由设置，可以由管理员改成取消即中断上游。
